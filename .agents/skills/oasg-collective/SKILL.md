name: oasg-collective
description: Check or execute OASG's opt-in finite collective workflow profile with CCR, VEK and OAWM, preserving evidence classes and each system's admission boundary.
---

Read [the supported profile](../../../docs/collective-profile.md) before native
integration work. Use `oasg collective support` to inspect exact installed
versions and content hashes. Missing or changed companions are unsupported;
do not silently fall back to mock acceptance or install dependencies at ingestion.

For evidence review, use `inspect`, `project`, `check` and `replay`. Retain raw
sources and each producer's digest. A checked projection is not execution
permission. Keep synthetic, executed finite software and separately authorized
operational evidence distinct.

For an authorized finite native test, choose an explicit empty disposable root
and run `oasg collective example --out <root> --execute`. The example executes
two CCR tasks separated by OASG policy improvement and native OAWM memory
admission, then withdraws the dependency. It must use the installed companion
interfaces; companion repositories remain read-only.

On failure, inspect the journal and preserve unresolved intents. Do not resend an
uncertain operation, erase incurred work, or restore an old passing memory to
bypass withdrawal. `reconcile --apply` performs source-bound accounting only; it
does not authorize a retry. Report the exact unresolved owning-system effect.

Changes to projection, verification, current eligibility or reconciliation need
negative tests and the per-module coverage gates in the release qualification.
Preserve the existing local gate, canonical bytes and synthetic/demo rejection.
Publication authorization and policy are separate from runtime admission.
