# Collective evidence and ownership

| Owner | Decision | The imported evidence cannot decide |
| --- | --- | --- |
| OASG | Whether this registered worker may change its workflow under the existing gate/lifecycle | CCR allocation, reward, OAWM admissibility |
| CCR | Fund, reserve, lease, accept signed results and reconcile source-bound accounting | Truth from an unsigned report |
| OAWM | Native procedural verification, promotion, receiver qualification and retirement | A copied receiver's eligibility or host execution permission |
| VEK | Verification requirements, packet conformance and a finite capacity model | Semantic truth, observed capacity, service credit |
| Host | Permit this exact current operation and its fixed executable | Authority embedded in retrieved text |

Candidate-only records have no admission. Locally admissible OASG changes still
need native OAWM verification and explicit host permission. Native-checked records
are not runtime-tested until the funded later task actually executes. The finite
software tests in this release do not establish operationally observed improvement.
Synthetic records remain synthetic and cannot satisfy active promotion.

The profile registers inputs, disjoint training/confirmation sets, freeze, expiry,
work bands, overhead, receiver, verifier key, whole checking/lifecycle code and
schema digest, worker digest, native registration and current library digest.
The reference oracle uses sorted adjacent elimination; the worker uses membership
probes. Raw traces and counters are independently reconstructed. Exact source
bytes, producer digests, positive witnesses and field maps accompany the projection.
Legacy canonicalization is used only in its own domain.

VEK core conformance can retain live semantic residuals. Capacity is model-only;
neither forecast is relabeled observed evidence. The exposed pure line-set worker
is intentionally bounded and does not support arbitrary commands, plugins,
effectful code, cross-tenant authority, empirical AI evaluation or global consensus.

The default later use totals 62 registered work units. A separately preregistered
output-loss control executes a fourth task, fails the native service check and
blocks subsequent qualified use; its measured work totals 70. It is labeled a
negative control and grants no positive evidence. Earlier valid history remains.
