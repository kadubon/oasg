# Experimental finite collective profile

This opt-in Alpha profile executes a finite software study through installed
CCR, OASG, VEK and OAWM public interfaces. It is currently under qualification;
this document does not announce a release. Legacy OASG commands, signing bytes,
schema exports, protected floors and gate/lifecycle rules are unchanged.

## Supported operation

The worker normalizes at most 64 lines from each bounded input, producing sorted
unique lines. The baseline scans a list; the registered candidate uses a set.
Both actually execute. A separate reference sorts and removes adjacent duplicates,
and an independent checker reconstructs membership-probe traces. The candidate
changes `set_routing_policy` for `local_reversible`; it cannot change grades,
inputs, verifiers, evidence classes, protected rules or the registered catalogue.

`oasg.collective.api` exposes closed records, `project`, `check_projection`,
`compare`, `check_trial`, `run_worker`, `execute_registered`, `withdraw`,
`reconcile`, `replay`, `support` and additive `schema_documents`.
`execute_registered(root, contract, registration, key=host_key)` accepts a
predeclared supported contract, exact CCR configuration and caller-held verifier
key. It requires an empty explicitly disposable root. It completes paired work,
local promotion, native procedural admission and fresh-process later use. The
caller retains the key for subsequent scoped withdrawal. Imported reports never
select the executable, module, public key or destination directory.

The convenience example registers a finite study and withdraws its dependency
after the second task, preserving the successful history:

```sh
uv sync --locked --group native
uv run --group native oasg collective support
uv run --group native oasg collective example --out /tmp/oasg-finite-study --execute
uv run --group native oasg collective replay /tmp/oasg-finite-study
uv run --group native oasg collective reconcile /tmp/oasg-finite-study --apply
```

Use an explicit empty platform-appropriate disposable path. Installation is a
separate operator action; ingestion and runtime operations never install packages
or fetch URLs. `support`, `inspect`, `project`, `check`, `status` and `replay` are
read-only. Omitting `--execute` or `--apply` returns a structured opt-in status.

## Owners and evidence

CCR creates and reserves formation, qualification and reuse work, grants current
leases and admits host-signed results. The host keeps its key outside subprocesses.
OASG independently checks finite observations, projects registered ordinal bands
and invokes the existing gate, shadow/lease lifecycle and library CAS. OAWM
separately observes its verification executions, proposes through its public port,
checks, promotes and admits receiver-qualified memory. VEK checks packets and a
finite capacity model; its forecast does not become observed capacity or a
reservation. CAIT analysis is consumed through CCR's source-bound reconciliation.

The later process reads the stored immutable memory version, checks the current
policy, receiver, inputs, dependency, expiry and CCR lease, and invokes OAWM's
action-bound execution path. Receiver B lacks its own qualification. Receiver C
is outside this registered profile. Neither a copied memory nor a local gate
receipt supplies the missing permission.

These are **executed finite software observations**, not an empirical agent or
intelligence-acceleration experiment. Synthetic controls remain synthetic even
when wrapped in a real subprocess. Host signatures authenticate scoped host
statements, not the physical world. Native acceptance, accounting totals and
packet hashes do not independently grant execution authority, rewards, capability
stock or cross-receiver eligibility.

## Measurement and projection

The unit is a registered membership probe plus declared control work. It is not
elapsed time, currency, CPU utilization or statistical independence. The default
study measures baseline 28 probes plus 2 control units and candidate 8 plus 2.
OAWM's separately executed formation/verification work contributes 14 units;
the later receiver use contributes 8. Independent replay totals 62 with stable
ultimate event IDs. Native OAWM/ALT cost valuation remains the upstream
`synthetic-work-v1` model; actual executions do not turn that valuation into money.

The registered budget coordinate is surplus only below the predeclared efficient
threshold, acceptable within the cap, otherwise blocked. Other protected floors
apply only to this fixed pure, exact-output, bounded, authenticated finite worker.
Unknown or nonpositive evidence blocks the projection. Claim emission and workflow
promotion action grades remain blocked. A same-band speed gain does not force a
strict gate improvement. Preparation/control overhead that removes the ordinal
gain leaves the old policy in place. Original JSON and producer digests accompany
every projection; CCR/OAWM/OASG canonical domains are kept separate.

New wire parsing rejects duplicate keys, floats, nonfinite numbers, booleans as
quantities, integers beyond signed 64-bit JSON bounds, unknown fields, excessive
depth/cardinality and malformed UTF-8. Text is inert data. Clock conversion is
exact UTC integer seconds; the host uses actual time, not simulated advancement.
New schema IDs use `urn:oasg:collective:*:v1`; no remote schema resolver is used.

## Compatibility and recovery limits

The packaged support manifest pins CCR 1.9.0, OAWM 0.2.0b0, VEK 1.3.0,
ALT 0.5.0 and CAIT 0.2.0, distribution hashes, source/schema/resource digests,
interpreter declarations and invoked surfaces. Same-version modified content is
rejected. The support report is descriptive and grants no authority.

CCR 1.9.0's CAIT creation export resolves receiver information from the first
registered action. This profile therefore fixes receiver A and lexically first
`formation`, and rejects other configurations. It does not rewrite original
history or claim arbitrary catalogue ordering support. OAWM's direct
`qualified.native.ccr_proposal` pins CCR 1.8.0 and is unsupported with this set;
the tested route uses native receiver qualification and OASG's CCR host adapter.

No transaction spans the three stores. The bounded local journal uses the existing
OASG lock/CAS, durable intents and original native acknowledgments. An interrupted
operation remains unresolved and blocks further use; it is not automatically
resent, paid twice or erased. Native OAWM remains single-writer. Withdrawal first
blocks the local scope, then records native retirement/lifecycle changes and local
policy rollback. Rollback restores policy only. It cannot undo external effects.
Read-only replay preserves historical results and explicitly requires a fresh
host check before any further execution.

The closed additive record set comprises contract, source, task binding, projection,
workflow export, lifecycle feedback, checkpoint and execution schemas. A whole
installed OASG checking/lifecycle code and schema commitment prevents a changed
checker from accepting an older contract under the same identifier. Dependency
installation metadata is not an authority source.

For a separately preregistered finite negative control, the Python `example`
helper accepts `negative_control=True`. A later actual execution loses its output;
native verification rejects service and restricts future use. Its fourth signed
CCR result records measured work without positive service. Independent replay
totals 70. Reconciliation after a later host withdrawal creates another immutable
source-bound snapshot and preserves the earlier as-of result.
